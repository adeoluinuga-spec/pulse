## Assessment

The missing planning UI has been delivered and the new payroll UI follows the
Appraisal design language. Pulse now has substantial connected functionality:
organisation structure, strategy, goals, KPIs, appraisal and payroll.

It is not yet a fully connected production HR platform. Several older dashboard
surfaces still simulate work, and payroll has control gaps that should be fixed
before real payment files are used. A passing test suite does not certify tax
rules, deployment permissions, or every end-to-end business journey.

## Findings requiring action

### High: report submission does not supply appraisal evidence

src/app/dashboard/reports/page.tsx:432 creates a local report after a timeout,
adds it to component state and displays “Your manager has been notified.”
There is no persistence or notification request in that submission handler.
Refreshing loses the new report. Appraisal reads database reports, so this UI
cannot supply the report-consistency component (20% in the default template).

Connect submission, report history, manager acknowledgement and notification to
authenticated server operations. Until then, do not present this path as saved.

### High: the older Performance dashboard contradicts the live workflow

src/app/dashboard/performance/page.tsx:72 defines fixed historical appraisal
scores; :727 initialises locally editable goals and subsequent changes stay in
component state. Users can reach it alongside the real /goals, /kpis and
/appraisal pages. A user can see invented history or update progress in the
wrong surface without updating the real goal.

Consolidate these views onto the live workspaces/data, or clearly remove the
demonstration actions and history from the production journey.

### High: bank destinations can change after payroll approval

src/app/api/payroll/runs/[runId]/export/route.ts reads approved amounts from
stored lines but bank/pension identifiers from current payroll profiles.
src/app/api/payroll/people/[employeeId]/route.ts allows a preparer to update those
profiles without approval of the change. Consequently, an approved run can
export to a different account after a preparer changes the profile.

Snapshot payment instructions for approval, or require a separately approved
bank-detail change and renewed payment-file approval. Logging a change is not
the same as authorising its destination.

### High: bonus import is not safe against concurrent duplicate requests

The performance import reads existing adjustments and then inserts, in separate
operations. The schema has no unique key for the originating appraisal within
a run. An isolated PGlite reproduction accepted two adjustments with the same
run, employee and appraisal source. A normal sequential retry is filtered, but
two concurrent imports can both pass the precheck.

Add a database uniqueness/idempotency rule and a transaction for import plus
audit. Also decide explicitly whether a single appraisal may fund bonuses in
more than one payroll period: the current deduplication scope is one run only.

References: src/app/api/payroll/runs/[runId]/performance/route.ts and
supabase/schema/11_payroll.sql (payroll_adjustments).

### High: payroll control reads and audit writes can fail silently

In src/lib/payrollServer.ts:
- loadSettings ignores the settings query error and can substitute defaults.
- contributorsOf ignores the event query error and can return no contributors.
- runStateFor ignores a failed blockers query and can treat it as zero blockers.
- logEvent ignores insertion failure, although contributor checks depend on events.

These are code-inspection findings, not a claim that a live failure occurred.
Abort on control-data errors and store workflow changes with their audit events
transactionally. The normal-path tests do not establish safe behavior on these
failure paths.

### High: an older evidence endpoint bypasses the reviewed workflow

POST /api/appraisals/evidence directly attaches/detaches goal/KPI links without
the canonical command's review-stage, revision and independent-review checks.
The new EvidenceMatcher correctly uses this endpoint only for GET previews and
uses /api/appraisals commands for writes. However, leaving the old POST callable
still provides an alternate HR write path around those rules.

Unify it with the canonical transactional command, or retire its write actions.
This finding does not mean released score snapshots automatically change;
it means attachment history and workflow protections are not consistently enforced.

### High before live payroll: statutory rules are explicitly unverified

src/lib/payrollRules.ts marks its rule sets unverified. The workspace warns the
operator, but the workflow does not require verified rules before approval.
Tests validate the implemented arithmetic; they do not establish that its
statutory assumptions are correct. PAYROLL_TAX_EXAMPLES.md is the review pack.

This audit makes no legal/tax validation claim. Obtain the appropriate rule
review and record/version its outcome before using real payment exports.

### Medium: large datasets can be truncated

Strategy/goals/KPIs and payroll input queries generally do not page through
results. When an organisation exceeds the configured PostgREST response cap,
rollups, compensation selection or payroll coverage may omit records without an
explicit warning. This is a scalability finding from code inspection, not a
demonstrated truncation in the current tenant.

### Medium: navigation does not reflect delegated payroll access

WorkSidebar shows Payroll only to HR/super-admin and executive-view roles.
The backend supports named payroll grants for other staff too. A legitimately
delegated standard user can be allowed at /payroll but have no sidebar link.
Use actual payroll capability when constructing navigation.

### Medium: polish and maintenance remain

- New planning and payroll screens match the navy/cobalt Appraisal theme.
- Strategy desktop and payroll desktop screenshots were inspected; planning and
  payslip mobile overflow checks pass.
- Long sidebar labels truncate and Appraisal appears under two groups.
- Goal search can leave an empty table rather than a useful no-results state.
- Success toasts can stack over page actions.
- Global lint reports 10 errors and 16 warnings, including two payroll effect
  errors and a planning test-harness rule error, alongside existing findings.
- PULSE_TODO.md, OPERATOR_ROADMAP.md and older verification totals are stale.
- The strategy migration exists as 20260910_000002_strategy_cascade.sql but has no
  dedicated counterpart in supabase/schema, unlike organisation/appraisal/payroll.
